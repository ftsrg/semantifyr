# Command Line

The `semantifyr` command lists, compiles, measures and verifies the verification cases of Semantifyr models. [`semantifyr-sysml`](#semantifyr-sysml) for SysML v2 models and [`semantifyr-gamma`](#semantifyr-gamma) for Gamma models share its verification options, output and exit codes. [Install](../start/install.md#the-command-line) builds each launcher, its distribution carrying the Theta backend. They need a Java 25 runtime and at least one verification backend.

<CodeBlock language="text">{help}</CodeBlock>

A model or library path is a `.semantifyr` file or a directory, which is searched recursively for `.semantifyr` files. `--log-level` before the command sets the level of the log on standard error, `warn` by default. At that level a warning or an error is one line, `warning: ` or `error: ` and its message; from `info` on, every line carries its time, its thread and its source.

`--case-name` selects cases by qualified name and overrides the tag filters. Without it, a command takes the cases that carry one of the `--include-tag` tags, or every case when none is given, except those that carry an `--exclude-tag` tag. What a command writes for a case, and where, is described under [Artifacts](artifacts.mdx); an artifact directory that cannot be created or written stops the command before it compiles anything.

## `verify`

<CodeBlock language="text">{verify}</CodeBlock>

`--timeout-seconds` bounds each case as a whole: its compilation, every backend run of the portfolio and the back-annotation of the witness. `--theta-executor` runs Theta from `PATH` (`shell`), in Docker (`docker`), or from `PATH` when it is there and in Docker otherwise (`auto`); `--theta-docker-image` is the image Docker runs, a `repository:tag` or `@digest` reference.

For each case, `verify` prints `Verifying <case> ...`, then the verdict with the time it took, compilation included, then the path of the `report.json` it wrote for the case. A case that does not compile gets `COMPILATION_ERROR` in place of the verdict and no report, and the compiler's message goes to standard error; a case whose witness cannot be back-annotated gets `BACK_ANNOTATION_ERROR` the same way. With `--quiet` it prints only the verdict of each case, one per line, as listed under [Verdicts](#verdicts), or `COMPILATION_ERROR` or `BACK_ANNOTATION_ERROR`.

With `--json` it prints one JSON object per case and line, as each case finishes:

```json
{"case":"semantifyr::verification::smoke::CounterReachesThree","exitCode":0,"report":"/tmp/semantifyr-123/smoke.semantifyr.verification.smoke.CounterReachesThree/report.json","compilationDuration":"PT0.158S","verificationDuration":"PT1.204S"}
```

`case` is the qualified name of the case, `exitCode` its [exit code](#exit-codes), `report` the absolute path of its `report.json`, `compilationDuration` the time the compilation took and `verificationDuration` the time from the compiled model to the verdict, both ISO 8601 durations. A case that does not compile or whose witness cannot be back-annotated has `phase`, `compilation` or `back-annotation`, and `error`, the message, instead of `report` and the durations:

```json
{"case":"semantifyr::verification::smoke::CounterReachesThree","exitCode":4,"phase":"compilation","error":"Property body must have a temporal operator (`AG` or `EF`) at the top level."}
```

`report.json` holds the rest, in these fields:

<ReportFields fields={reportFields} />

`result.metadata.backendId` names the backend configuration that answered and `result.message` carries its message.

`result.soundness` and `result.isTrusted` say how far the verdict can be trusted. `result.soundness` is the [soundness direction](../backends/portfolios-and-verdicts.mdx#soundness-directions) of the backend configuration that answered. `result.isTrusted` says whether that direction backs the verdict, and a portfolio reports `PASSED` or `FAILED` only for an answer it backs. A portfolio of one backend configuration turns an answer it does not back into `INCONCLUSIVE`, with no witness and a message that names the backend, its verdict and its direction. A portfolio of several passes over such an answer, and when none of its configurations gives one it backs, it ends in `TIMEOUT`, `ERRORED`, `NOT_SUPPORTED` or `INCONCLUSIVE`, with a message that names what the configurations answered or, when every one failed, their failures.

### Verdicts

The launchers print six verdicts. Live shows four, the word of each in the table: it names the exact verdict, and shows a timeout and a not supported answer as inconclusive.

<LauncherVerdicts verdicts={verdicts} />

A case is `PASSED` when its property holds and `FAILED` when it does not. Otherwise it is `INCONCLUSIVE` when the backends finished without a verdict the portfolio trusts (see [soundness directions](../backends/portfolios-and-verdicts.mdx#soundness-directions)), `TIMEOUT` when the time limit ran out before a backend decided, `NOT_SUPPORTED` when the chosen backend refuses a construct of the model or stops a run on a value outside the range it declared (the pages of [Theta](../backends/theta.mdx), [nuXmv](../backends/nuxmv.mdx), [Spin](../backends/spin.mdx) and [Uppaal](../backends/uppaal.mdx) say what each refuses and where it stops; the message names each construct or variable and its source line), or `ERRORED` when a backend run failed, a backend rejected the model it was given (the message carries the backend's text) or, in a portfolio that waits for every backend configuration, trusted answers disagreed.

## `compile`

<CodeBlock language="text">{compile}</CodeBlock>

For each case, `compile` prints `Compiling <case> to <file>`, writes the inlined model to the file, and prints the [directory holding the artifacts](artifacts.mdx#the-case-directory) of the case. With one selected case, `--output` is the file, `<model>.inlined.semantifyr` next to the model by default; with several, it is a directory, `<model>.inlined` next to the model by default, holding a file for each case named as its case directory, with `.semantifyr` appended.

## `metrics`

<CodeBlock language="text">{metrics}</CodeBlock>

For each case, `metrics` prints the size of the input model, of the inlined model and of the flattened model a backend receives, each as its number of variables, operations and expressions. With `--json` it prints one JSON object per case and line, with `case` and the sizes under the keys `report.json` has under `result.metrics.verifier.compilation`:

```json
{"case":"semantifyr::verification::smoke::CounterReachesThree","inputSize":{"variables":1,"operations":4,"expressions":13},"inlinedSize":{"variables":1,"operations":5,"expressions":15},"flattenedSize":{"variables":1,"operations":5,"expressions":12}}
```

`metrics` and `verify` report the same sizes for the same case and compilation options.

## `semantifyr-sysml`

`semantifyr-sysml` verifies SysML v2 models. Its distribution, `semantifyr-sysml-<version>.zip`, carries Theta, the SysML v2 semantic library in `libraries/sysmlv2` and the model of [Verifying SysML v2 Models](../frontends/sysml-v2/verifying.md) as `models/smoke/room.sysml`. It translates a model to a Semantifyr model with the bundled SysIDE fork, which runs on Node.js, so it needs `node` on `PATH`; without it, translating fails with exit code 4 and a message naming `node`. The translator reads every `.sysml` and `.kerml` file below the model's directory as the model's workspace, so keep other models and the artifact directory out of that directory. Translations are cached under `~/.semantifyr/sysml-cache`, keyed by the model and its workspace ([Folders](#folders)).

<CodeBlock language="text">{sysmlHelp}</CodeBlock>

### `semantifyr-sysml verify` {#sysml-verify}

<CodeBlock language="text">{sysmlVerify}</CodeBlock>

`verify` translates the model and verifies its cases with the options, output and [exit codes](#exit-codes) of [`semantifyr verify`](#verify). The case names start with `semantifyr::sysml::model`, the package the translator gives every model. The translated model stays under the artifact directory, and for each case with a witness `verify` writes the witness as a SysML v2 model, `trace.sysml`, next to the case's `report.json` ([Artifacts](artifacts.mdx), [SysML v2 traces](../frontends/sysml-v2/traces.mdx)); a witness the generator cannot express keeps its verdict, gets no `trace.sysml` and a warning in the log.

The translation is verified on top of the bundled SysML v2 semantic library, the state-level library in `libraries/sysmlv2`. `--library` loads files of the Semantifyr Language in addition to it and does not replace it.

### `semantifyr-sysml compile` {#sysml-compile}

<CodeBlock language="text">{sysmlCompile}</CodeBlock>

`compile` writes the translation of the model, a Semantifyr model, to `--output`, by default next to the model with the `.semantifyr` extension, and the name map from the model's elements to the Semantifyr model beside it with the `.names.json` extension. A construct the translator refuses is an error at its line and no Semantifyr model is written; a warning is printed and the translation written ([Supported Language](../frontends/sysml-v2/supported.mdx)). `semantifyr` verifies it together with that library: `semantifyr verify -l <semantifyr-sysml distribution>/libraries/sysmlv2 room.semantifyr`.

## `semantifyr-gamma`

`semantifyr-gamma` verifies Gamma models, `.gamma` or `.gcd` files in the [sub-language of Gamma](../frontends/gamma/supported.mdx) the frontend supports, written in Gamma's syntax: statecharts, their composition and their verification cases. The Gamma models in the model's directory are its workspace, in which its imports resolve; `--workspace <directory>` makes the `.gamma` and `.gcd` files of that directory, recursively, the workspace instead, for a model that imports from another directory. It compiles a model to a Semantifyr model on top of the bundled Gamma semantic library. Its distribution, `semantifyr-gamma-<version>.zip`, carries Theta, the library in `libraries/gamma` and the example model `models/smoke/Simple.gamma`.

<CodeBlock language="text">{gammaHelp}</CodeBlock>

### `semantifyr-gamma verify` {#gamma-verify}

<CodeBlock language="text">{gammaVerify}</CodeBlock>

`verify` compiles the model and verifies its cases with the options, output and [exit codes](#exit-codes) of [`semantifyr verify`](#verify). A case is named by its Gamma qualified name, such as `Simple.WorkerStatechartIdleReachable`; without `--case-name`, `verify` verifies every case of the model. For each case with a witness, `verify` writes the witness as a Gamma execution trace, `trace.get`, next to the case's `report.json` ([Artifacts](artifacts.mdx), [Gamma traces](../frontends/gamma/traces.mdx)).

### `semantifyr-gamma compile` {#gamma-compile}

<CodeBlock language="text">{gammaCompile}</CodeBlock>

`compile` writes the Semantifyr model of a Gamma model to `--output`, by default next to the model with the `.semantifyr` extension. Every Gamma name is written with a leading underscore, `Main` as `_Main`, so none equals a library member or a keyword of the Semantifyr Language. `semantifyr` verifies it together with that library: `semantifyr verify -l <semantifyr-gamma distribution>/libraries/gamma Simple.semantifyr`.

## Folders

Besides the [artifact directory](artifacts.mdx), a launcher writes under `~/.semantifyr` in the user's home directory and in the system's temporary directory.

Under `~/.semantifyr` it unpacks what it carries, each into a folder named by the SHA-256 digest of its contents. It fills the folder under another name and then renames it, so a launcher never reads half of one; a folder is never written again, and the folders of older digests stay until they are deleted by hand.

- `builtin/<digest>/`: the standard library, `standard.semantifyr`, unpacked by every launcher.
- `gamma/default/<digest>/`: the Gamma semantic library, unpacked by `semantifyr-gamma`.
- `sysmlv2/default/<digest>/`: the SysML v2 semantic library, unpacked by `semantifyr-sysml verify`.
- `sysml-cli/<digest>/`: the SysML v2 translator with the SysML v2 standard library, unpacked by `semantifyr-sysml`.
- `sysml-cache/<translator digest>/`: the translations of `semantifyr-sysml`, a Semantifyr model and its name map for each model, named after the model file and a digest of every `.sysml` and `.kerml` file in the model's directory and below it, so a model is translated again only when one of those files or the translator changes.

In the temporary directory, `verify` and `compile` without `--artifact-directory` write the artifacts into a new `semantifyr-<number>` directory, which they leave in place; `metrics` compiles in a `semantifyr-metrics-<number>` directory, which it deletes when it ends.

## Exit codes

<ExitCodeTable codes={exitCodes} />

Codes 2 to 4, code 10 and an unavailable portfolio stop the command before it verifies anything, or, in `compile` and `metrics`, at the case that does not compile. Every launcher's `verify` runs every case, including those after a case that does not compile, and exits with the highest of their codes: 0 means every case passed, 4 that some case did not compile and the rest passed, 5 that some case failed and the rest passed, failed or did not compile.
