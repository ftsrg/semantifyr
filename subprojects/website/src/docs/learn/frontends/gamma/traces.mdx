# Gamma Traces

`semantifyr-gamma verify`, the VS Code extension, and Live show the run of a case as a Gamma execution trace, `trace.get`, which any Gamma tool reads next to the model.

The trace of `BarrierDownWhileTrainInCrossing` from the [lesson](lesson.md):

<CodeBlock language="gamma">{trace}</CodeBlock>

- `import` names the case's package, and `trace <name> of <case>` names the traced case; every name resolves in the scope of the case's component.
- Instances are named from the traced component down, nested ones as `outer->inner`.
- The first step is initialization: the `reset` act, the outputs the entry actions raised, and the state reached.
- A step's acts are what the environment did: `raise <port>.<event>` raises an input event, `elapse <milliseconds>` is the time that passed before the step, and `schedule component` runs the component for one step.
- A step's asserts are what followed: the active `state` of every region, the `variable` values, the output events an instance raised, and every fired `transition`, with `when <trigger>` where another transition shares its source and target.

The trace differs from Gamma's own: its header names a verification case, where Gamma's names a component; the `transition` assert is Semantifyr's own; an `elapse` of a fraction of a millisecond is written over its denominator, as in `elapse 2000/3`, where Gamma's takes whole milliseconds; and it asserts nothing of an event that was not raised, where Gamma's back-annotation negates each. The values of event parameters are planned for the trace, and the `assign` act, `schedule` of an instance, and a final cycle are not supported.
