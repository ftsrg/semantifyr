# Command Line

The `semantifyr` command lists, compiles, measures and verifies the verification cases of OXSTS models. `semantifyr-sysml` for [SysML v2 models](sysml.mdx) and `semantifyr-gamma` for [Gamma models](gamma.mdx) share its verification options, output and exit codes. Each launcher is built from source with `./gradlew :semantifyr-cli:installDist`, `:sysml-cli:installDist` or `:gamma-cli:installDist`, its distribution carrying the Theta backend ([Getting Started](../getting-started.md#option-c-install-the-command-line-interface-for-scripts-and-ci)); `semantifyr` is then `subprojects/semantifyr-cli/build/install/semantifyr/bin/semantifyr`. They need a Java 25 runtime and at least one verification backend.

<CodeBlock language="text">{help}</CodeBlock>

A model or library path is an `.oxsts` file or a directory, which is searched recursively for `.oxsts` files. `--log-level` before the command sets the level of the log on standard error, `warn` by default. At that level a warning or an error is one line, `warning: ` or `error: ` and its message; from `info` on, every line carries its time, its thread and its source.

`--case-name` selects cases by qualified name and overrides the tag filters. Without it, a command takes the cases that carry one of the `--include-tag` tags, or every case when none is given, except those that carry an `--exclude-tag` tag. What a command writes for a case, and where, is described under [Artifacts](artifacts.mdx); an artifact directory that cannot be created or written stops the command before it compiles anything.

## `verify`

<CodeBlock language="text">{verify}</CodeBlock>

`--timeout-seconds` bounds each case as a whole: its compilation, every backend run of the portfolio and the back-annotation of the witness. `--theta-executor` runs Theta from `PATH` (`shell`), in Docker (`docker`), or from `PATH` when it is there and in Docker otherwise (`auto`); `--theta-docker-image` is the image Docker runs, a `repository:tag` or `@digest` reference.

For each case, `verify` prints `Verifying <case> ...`, then the verdict with the time it took, compilation included, then the path of the `report.json` it wrote for the case. A case that does not compile gets `COMPILATION_ERROR` in place of the verdict and no report, and the compiler's message goes to standard error; a case whose witness cannot be back-annotated gets `BACK_ANNOTATION_ERROR` the same way. With `--quiet` it prints only the verdict of each case, one per line, as listed under [Verdicts](#verdicts), or `COMPILATION_ERROR` or `BACK_ANNOTATION_ERROR`.

With `--json` it prints one JSON object per case and line, as each case finishes:

```json
{"case":"semantifyr::verification::smoke::CounterReachesThree","exitCode":0,"report":"/tmp/semantifyr-123/smoke.semantifyr.verification.smoke.CounterReachesThree/report.json","compilationDuration":"PT0.158S","verificationDuration":"PT1.204S"}
```

`case` is the qualified name of the case, `exitCode` its [exit code](#exit-codes), `report` the absolute path of its `report.json`, `compilationDuration` the time the compilation took and `verificationDuration` the time from the compiled model to the verdict, both ISO 8601 durations. A case that does not compile or whose witness cannot be back-annotated has `phase`, `compilation` or `back-annotation`, and `error`, the message, instead of `report` and the durations:

```json
{"case":"semantifyr::verification::smoke::CounterReachesThree","exitCode":4,"phase":"compilation","error":"Property body must have a temporal operator (`AG` or `EF`) at the top level."}
```

`report.json` holds the rest, in these fields:

<ReportFields fields={reportFields} />

`result.metadata.backendId` names the backend configuration that answered and `result.message` carries its message.

`result.soundness` and `result.isTrusted` say how far the verdict can be trusted. `result.soundness` is the [soundness direction](portfolios.mdx#soundness-directions) of the backend configuration that answered: an exact configuration is trusted on every verdict, an over-approximating one on a verdict that needs no trace (a passed `AG`, a failed `EF`), an under-approximating one on a verdict that a trace backs (a failed `AG`, a passed `EF`). `result.isTrusted` says whether the portfolio trusted the answer. A portfolio reports `PASSED` or `FAILED` only for an answer it trusts, so `isTrusted` is true for those two verdicts and false for every other: an answer that its configuration's direction does not back becomes `INCONCLUSIVE`, with no witness and a message that names the backend, its verdict and its direction.

### Verdicts

The launchers print six verdicts. Live shows four, the word of each in the table: it names the exact verdict, and shows a timeout and a not supported answer as inconclusive.

<LauncherVerdicts verdicts={verdicts} />

A case is `PASSED` when its property holds and `FAILED` when it does not. Otherwise it is `INCONCLUSIVE` when the backends finished without a verdict the portfolio trusts (see [soundness directions](portfolios.mdx#soundness-directions)), `TIMEOUT` when the time limit ran out before a backend decided, `NOT_SUPPORTED` when the chosen backend refuses a construct of the model (the pages of [Theta](../backends/theta.mdx), [nuXmv](../backends/nuxmv.mdx), [Spin](../backends/spin.mdx) and [Uppaal](../backends/uppaal.mdx) list what each refuses and why) or a value leaves the range Uppaal declared for its variable (the message names each construct or variable and its source line), or `ERRORED` when a backend run failed, a backend rejected the model it was given (the message carries the backend's text) or trusted backends disagreed.

## `compile`

<CodeBlock language="text">{compile}</CodeBlock>

For each case, `compile` prints `Compiling <case> to <file>`, writes the inlined model to the file, and prints the [directory holding the artifacts](artifacts.mdx#the-case-directory) of the case. With one selected case, `--output` is the file, `<model>.inlined.oxsts` next to the model by default; with several, it is a directory, `<model>.inlined` next to the model by default, holding a file for each case named as its case directory, with `.oxsts` appended.

## `metrics`

<CodeBlock language="text">{metrics}</CodeBlock>

For each case, `metrics` prints the size of the input model, of the inlined model and of the flattened model a backend receives, each as its number of variables, operations and expressions. With `--json` it prints one JSON object per case and line, with `case` and the sizes under the keys `report.json` has under `result.metrics.verifier.compilation`:

```json
{"case":"semantifyr::verification::smoke::CounterReachesThree","inputSize":{"variables":1,"operations":4,"expressions":13},"inlinedSize":{"variables":1,"operations":5,"expressions":15},"flattenedSize":{"variables":1,"operations":5,"expressions":12}}
```

`metrics` and `verify` report the same sizes for the same case and compilation options.

## Folders

Besides the [artifact directory](artifacts.mdx), a launcher writes under `~/.semantifyr` in the user's home directory and in the system's temporary directory.

Under `~/.semantifyr` it unpacks what it carries, each into a folder named by the SHA-256 digest of its contents. It fills the folder under another name and then renames it, so a launcher never reads half of one; a folder is never written again, and the folders of older digests stay until they are deleted by hand.

- `builtin/<digest>/`: the standard library, `semantifyr.oxsts`, unpacked by every launcher.
- `gamma/default/<digest>/`: the Gamma semantic library, unpacked by `semantifyr-gamma`.
- `sysmlv2/default/<digest>/`: the SysML v2 semantic library, unpacked by `semantifyr-sysml verify`.
- `sysml-cli/<digest>/`: the SysML v2 translator with the SysML v2 standard library, unpacked by `semantifyr-sysml`.
- `sysml-cache/<translator digest>/`: the translations of `semantifyr-sysml`, an OXSTS file and its name map for each model, named after the model file and a digest of every `.sysml` and `.kerml` file in the model's directory, so a model is translated again only when one of those files or the translator changes.

In the temporary directory, `verify` and `compile` without `--artifact-directory` write the artifacts into a new `semantifyr-<number>` directory, which they leave in place; `metrics` compiles in a `semantifyr-metrics-<number>` directory, which it deletes when it ends.

## Exit codes

<ExitCodeTable codes={exitCodes} />

Codes 2 to 4, code 10 and an unavailable portfolio stop the command before it verifies anything, or, in `compile` and `metrics`, at the case that does not compile. Every launcher's `verify` runs every case, including those after a case that does not compile, and exits with the highest of their codes: 0 means every case passed, 4 that some case did not compile and the rest passed, 5 that some case failed and the rest passed, failed or did not compile.
