# Gamma traces

`semantifyr-gamma verify`, the VS Code extension and Live's Gamma language write the witness of a Gamma case as a Gamma execution trace, `trace.gamma`, next to the back-annotated [`witness.oxsts`](artifacts.mdx#witnessoxsts). The trace is a file of the model's package in the trace sub-language of the Gamma grammar, modelled after Gamma's `ExecutionTrace`: a sequence of steps, each with the acts of the environment and the asserts that hold after it. Every path in it is a cross-reference into the model, so the Gamma language checks a trace like any other Gamma file.

## Form

The reference trace, of the case `ACanBeGreen` of the Crossroads example, which the Gamma frontend's tests generate from its `witness.json` and `trace.json` and compare whole:

<CodeBlock language="gamma">{trace.replace(/^\/\*[\s\S]*?\*\/\s*/, '')}</CodeBlock>

- `trace <name> of <case>` names the traced verification case. The trace sits in the case's package, so it resolves the case across files, in a resource set and through the language server's index.
- Every path starts at the component instance of the case, `system` here, and navigates through component instances, ports, regions and states.
- The first step is initialization: the `reset` act, the events raised during initialization, and the state reached.

Acts:

- `raise <port>.<event>`: the environment raises an input event of a port of the component.
- `schedule component`: the component takes one step.
- `elapse 1 s`: time advances by one time step.

Asserts:

- `transition <state> to <state>`: a transition fired; `when <trigger>` follows when another transition shares its source and target.
- `raise <port>.<event>`: the component raised an output event.
- `state <state>`: a leaf state is active.
- `variable <variable> == <value>`: a statechart variable has a value.

The Gamma validator checks that a path starts at the case's component instance, that an act raises an input event and an assert an output event of its port, that a state assert names a state, that a fired transition exists and is unambiguous, and that a value matches its variable's type.

## What the trace shows

The Gamma semantic library marks four transitions with `@Trace`: `Transition::fire`, `Port::raiseInputEvent(event)`, `Port::setOutputEvent(event)` and `GammaVerificationCase::passTime`, which the trace shows as:

- a fired `Transition::fire` as a `transition` assert;
- `Port::raiseInputEvent` as a `raise` act and `Port::setOutputEvent` as a `raise` assert;
- `passTime` at the root as `elapse 1 s`;
- the active state of every region and the value of every statechart variable in the witness as `state` and `variable` asserts, leaf states only.

Input events are traced because the library resets them within the step, so no state between steps shows them. Output events are traced because the optimizer removes outputs that nothing reads, and two raises on one port in a step would show as one.

Not in the trace: transitions with the same source, target and trigger (the validator reports them as ambiguous), and timers and port variables. The time step is fixed at one second, and the trace is not written in the `.get` format of the Gamma framework.

The VS Code extension's language server opens a `trace.gamma` like any Gamma file, and Live's Gamma language shows the trace in the *Gamma trace* view of the trace under the cases.
