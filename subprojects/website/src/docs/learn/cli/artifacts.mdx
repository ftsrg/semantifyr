# Artifacts

A verification writes the artifacts of each case into a directory of its own: what the compiler made of the model, what each backend was given and printed, the report, and for a verdict with a witness the witness and its trace. The launchers write the case directories into `--artifact-directory`, the VS Code extension where `semantifyr.artifacts.location` says, and Live into the working folder of the session, which it deletes when the session ends ([What Live keeps](../live-privacy.md)).

## The case directory

A case directory is named after the model file without its extension and the qualified name of the case, joined by `.`, with `::` written as `.` and every character other than a letter, a digit, `.`, `_` and `-` as `_`. A name longer than 64 characters keeps its first 55 and ends in `-` and an eight-digit hexadecimal hash of the whole. A verification empties the directory before it writes. The case `semantifyr::verification::smoke::CounterReachesThree` of `smoke.oxsts` is in `smoke.semantifyr.verification.smoke.CounterReachesThree`.

`--artifacts` chooses which artifacts are written: `none`, `all`, the default, or `debug`; `--enable-artifact` and `--disable-artifact` add and remove one by the name in parentheses below. The VS Code extension's `semantifyr.artifacts.preset` setting chooses the same.

- `report.json`, for every case that compiles: the verdict, the backend that answered and the times and sizes of the run, in the fields listed under [`verify`](index.mdx#verify).
- `pipeline/instantiated.oxsts` (`instantiated-model`), `pipeline/inlined.oxsts` (`inlined-model`) and `pipeline/flattened.oxsts` (`flattened-model`): the model after each phase of the compilation, each an [inlined model](#inlined-models).
- `mapping.json` (`mapping`): the number that stands for each instance in the flattened model, the instance named by its path from the root instance, as `{"instances": [{"name": ..., "id": ...}]}`.
- `pipeline/steps/` (`compilation-step`, in `debug` only): the model after every pass of the compiler, numbered in the order they ran and named after the pass, such as `000000_expressioncallinlining.oxsts`.
- The files of each backend run: the model the backend was given (`inlined.xsts` for Theta, `model.smv` for nuXmv, `model.pml` for Spin, `model.xml` and `model.q` for Uppaal) and what the backend printed. A portfolio that runs several backend configurations gives each a subdirectory of its own.
- `witness.oxsts`, `witness.json` and `trace.json`, for a verdict with a witness: a failed `AG` property or a passed `EF` property, which an execution of the model shows. `semantifyr-sysml` writes `trace.sysml` beside them ([SysML v2 traces](sysml-trace.mdx)), `semantifyr-gamma` `trace.gamma` ([Gamma traces](gamma-trace.mdx)).
- `validation/`: the case directory of the last [witness validation](#witness-validation), with the same files.

`semantifyr-sysml` writes the translation of the model into `compiled/default/<model>.oxsts` at the top of the artifact directory, with its [name map](sysml-trace.mdx#the-name-map), `<model>.names.json`, beside it, and the case directories next to `compiled/`. `semantifyr-gamma` gives every case a directory named after its Gamma qualified name, holding the compiled model, `model.oxsts`, and the case directory under `verification/`.

## Inlined models

The models under `pipeline/`, `semantifyr compile`'s output and the witness are inlined models: one file that names the class it was compiled from and holds everything a backend needs, with no class of its own. An inlined model is `inlined oxsts of`, or `witness of` for a witness, and the qualified name of the class, then its variables, the feature `root` that holds the instance of the class, the `init` and the main transition, and the property, an expression without `return`. Names that were members of instances are paths from the root instance, such as `root.counter.value`. An inlined model is OXSTS and validates, compiles and verifies as any other model.

```oxsts
inlined oxsts of semantifyr::Anything

var counter: int := 0

init {
    counter := 0
}

tran {
    choice {
        counter := counter + 1
    } or {
        counter := 0
    }
}

prop {
    AG counter >= 0
}
```

## `witness.oxsts`

The witness is the execution a backend found, back-annotated into OXSTS as an inlined model of the verified class that has exactly that execution. It declares `var step: int := 0` and holds the class as `root`. Its `init` assumes `step == 0`, runs the class's `init`, assumes the value of every variable in the initial state and sets the next step; each further step is a branch of its main transition that assumes the step's number, runs the class's main transition, assumes the values of the state after it and sets the number of the next step. Its property is the class's own for a passed `EF` and its negation for a failed `AG`, so a valid witness passes when it is verified again.

## `witness.json`

The state of every step of the witness, named as in `witness.oxsts`: `initializedStep` is the initial state, the one `init` produces, and `steps` holds one state for each step after it. Each value is OXSTS text: a literal, `nothing`, or an instance by its path, a global one by its qualified name.

## `trace.json`

The calls of transitions annotated [`@Trace`](../language/standard-library.md#trace) in each step of the witness, aligned step for step with `witness.json`. A call is listed in the step it fired in with its receiver, `self`, the qualified name of the transition, the value of each argument by parameter, and in `innerTraces` the traced calls made in its body.

## Witness validation

A witness is validated by verifying `witness.oxsts` again, on the portfolio of the verification or on another one, into the `validation/` directory of its case, so that the verification's artifacts and the open witness stay as they are. The result is valid when the witness verifies `PASSED`, invalid when it verifies `FAILED`, inconclusive when it verifies `INCONCLUSIVE`, `TIMEOUT` or `NOT_SUPPORTED`, and errored when it verifies `ERRORED`, the case has no witness or the witness does not load. It carries that verdict, the portfolio, the backend that answered and its message.

The VS Code extension validates after every verdict with a witness while `semantifyr.verification.autoValidate` is on, and from **Validate Witness** on the case. Live validates every case with a witness while auto-validation is on, and from **Validate** in the case's row. An OXSTS witness is named by its location in `witness.oxsts`, a Gamma witness by the location of its case, whose last verification left the witness among its artifacts.
