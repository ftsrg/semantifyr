# Gamma's Semantic Assumptions

The Gamma frontend gives a model the meaning Gamma gives it, as the Gamma semantic library writes it in OXSTS, except in the differences it declares at the end of this page. This page states what the library assumes where Gamma leaves a choice or where the library simplifies, and those differences.

## The Step

A verification runs the component of its case in steps, from the state its `init` reaches. Each step does four things in order:

1. The output events raised in the step before are cleared.
2. The environment raises any of the component's input events, each with any value of its parameters, or none.
3. Time passes by one delta.
4. The component runs once, as its kind of composition runs its parts.

## Time

Every step advances time by a fixed delta of one second, the same for every timeout. A timeout that was never set is up from the start. A timeout that is set counts down by the delta in every step while it is above zero, and is up from the moment it reaches zero: it stays up until it is set again. A timeout is therefore up after as many steps as its value has started seconds, so a timeout shorter than a second, 500 ms say, is up after the first step, as a timeout of one second is, and one of 1500 ms after the second.

## Events

An output event raised in a step stays raised until the next step starts, so a case's property sees it in the state after the step. An input event lasts for the step it arrives in. An asynchronous adapter is the exception, as the next section states.

## Asynchronous Composition

An asynchronous component takes part in the step with three differences: the environment puts messages into its queues instead of raising its input events, the output events of its adapters are not cleared when the step starts, and its run is a turn of its adapters.

### Turns

An asynchronous composite gives one of its adapters a turn in a step, any one of them; a scheduled asynchronous composite gives a turn to every entry of its execution list, in its order; an adapter that is the case's component has one turn in a step. In its turn an adapter takes one message from its queues and does what its control specification names for it: it runs the wrapped component once, resets it, clears queues, or does nothing. A message taken without a run leaves its event raised until the component's next run, unless a reset clears it, so that run sees it together with the event of the message that runs it. A turn of an adapter whose queues are empty does nothing, so a step may run no component; such a step is still a step, time passes in it, and a property over every state and one over some state both count the state after it.

### Queues and the Environment

A message waits in its queue until a turn takes it. The environment puts messages only into the queues that store messages of the system's ports alone, in every step up to the queue's capacity, each one of any event the queue stores with any values of its parameters, or none, and never into a full queue. Into a queue below another queue of its adapter in priority it puts a message only while that queue and the queues above it hold fewer messages than the adapter has turns in a step, as Gamma's analysis does.

### Clocks

A clock counts the time that passes in the step and is up once its count reaches its rate. When the asynchronous component's schedule starts, after time has passed and before any adapter takes its message, every clock that is up starts counting from zero again and puts a tick into each queue that stores it, so a tick can be taken in the step it is put in.

### Events of an Adapter

An adapter clears the wrapped component's output events when it runs the component. An output bound to a port of the system, which a case's property can see, stays raised until the adapter runs or resets the component again. An output that a channel carries into a queue is put into the queue in the adapter's turn and reset there. An output that is bound to a port of the system as well is not reset there: it stays raised and is put into that queue again at every later turn of its adapter, once for each entry of an execution list that names the adapter, until the adapter runs or resets the component.

### Reset

A queue reset on the same message takes the place of the `reset` control function. The reset leaves the timeouts, which the states it enters set, the queues and the clocks as they are.

## What a Verdict Covers

The fixed delta is an abstraction: Gamma lets a range of time pass between two steps, which its analysis constrains, and the library keeps the runs in which exactly one second passes, for timeouts and clocks alike. A passed `AG` and a failed `EF` hold over the runs the library keeps, and a run with another delay may break them. Apart from its clocks and its deviating constructs, the asynchronous composition keeps the runs of Gamma's analysis with the optimization of the environment's queues switched off, the environment's bound on a queue of lower priority included, since that bound is Gamma's own. Gamma's default analysis differs: it shrinks a queue the environment fills to the smaller of its capacity and the adapter's turns in a step, and it gives an adapter at the root no queue, where the library keeps every queue as written. A failed `AG` and a passed `EF` rest on one run the library found, in which a second passes every step, and which Gamma admits too unless a deviation is involved in it: then the run may be one Gamma excludes.
