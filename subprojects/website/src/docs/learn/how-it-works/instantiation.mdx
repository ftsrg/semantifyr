# Instantiation

Instantiation is the first phase of the compilation. Before it, the compiler wraps the case in a root: a model that contains one instance of the case's class, named `root`, and calls its `init`, its main transition and its property. Instantiation leaves that text as it is. What it builds is the instance tree, the instances the system is made of.

It takes the instances in the order it reaches them, breadth first, starting from the model, and gives every containment of multiplicity one of each instance an instance of its own, which it then reaches in turn. A containment marked `@Shared` gets one instance, shared by every instance that holds it, and a containment with an `opposite` is placed on both sides. Only containments get instances here: references and bound features point into the tree and are evaluated against it later, when inlining and flattening ask for them.

`root.left` and `root.right` are two instances of the same class, `Lamp`, and each has its own `on`. The later phases read the tree: [inlining](inlining.mdx) takes each call's body from the class of the instance it is called on, and [flattening](flattening.mdx) makes one variable of every variable of every instance.
