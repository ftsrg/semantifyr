# Uppaal

[Uppaal](https://uppaal.org/) is a model checker for networks of timed automata. The backend transforms a case into a timed automaton.

## Install

[Install Uppaal](https://uppaal.org/) and put its `verifyta` on `PATH`; a typical install has it under `<uppaal>/bin-Linux/verifyta`.

## Verdicts

Uppaal havocs an integer only among candidate values, so its configurations are under-approximating: a portfolio trusts a trace they find, not a proof. The exception is `over-approximation` (`-A`, the convex hull of clock zones), which over-approximates the clock zones and is trusted when it finds no trace.

## Time

Uppaal realizes the [wait before every main step](../language/reference/classes-and-behaviour/time.md#the-wait-before-a-step) over dense time with its own clocks. Its trace is a path through clock zones that names no times; the backend reads back the earliest times that path allows, so the elapsed times and clock values of its trace are one run along the path Uppaal found.

## Integers

The backend declares every integer with its static bound, or with a 31-bit range when it has none within 32 bits, so that an increment or a doubling cannot wrap before Uppaal checks the range. When a value leaves the declared range, the run stops as Not supported, naming the variable, so a trace never passes through a wrapped value. A proof over a counter without a guard, such as `if (counter < 10) { counter := counter + 1 }`, counts through the whole range and does not finish in practice.

## What the backend refuses

The backend answers Not supported, naming each construct, or the variable it concerns, and its source line, when a case holds one of these:

- Variables of type `real`, `string`, or `any`: the Uppaal transformation declares integer, boolean, enumeration, and clock variables only.
- For-operations: the Uppaal transformation has no loop.
- String literals: Uppaal has no strings.
- Array literals: the backend receives arrays split into one variable per slot and has no form for an array value.
- Array indexing: the backend receives arrays split into one variable per slot and has no form for indexing.
- Clocks read outside the condition of an `assume` or an `if`, such as a clock test stored in a variable or chosen by an if-then-else: the transformation turns clock tests into guards of the automaton's edges, and Uppaal reads a clock nowhere else.
- Clock bounds beyond 1073741822: `verifyta` refuses a clock constraint whose constant has a larger magnitude.
- Arithmetic that may leave the 32-bit range: Uppaal's arithmetic wraps at 32 bits before its range check can stop the run; the property depends on the arithmetic.
- In the `over-approximation` configuration, havoced integers read other than in comparisons with literals: Uppaal chooses a havoced integer among candidate values, which under-approximates a variable read this way, and a run is never both over- and under-approximating.
