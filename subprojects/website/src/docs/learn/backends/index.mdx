# Backends

A backend is a model checker that Semantifyr runs on the formal model of a verification case. It never sees the engineering language: whatever the frontend, the compiler hands it the case as a [transition system](../oxsts/compilation/index.mdx), which the backend translates into its own input language, and [Artifacts](../reference/artifacts.mdx) lists what each run writes.

Before it runs, a backend checks that it can translate the model, and answers Not supported, naming each construct it refuses, when it cannot; each backend's page lists what it refuses and why.

A backend's answer is a verdict on the case's property, trusted in the direction of the configuration that gave it: an exact one both ways, an under-approximating one when it finds a trace, an over-approximating one when it finds none. A portfolio runs the backends side by side and decides the verdict from the answers it trusts, as [Portfolios and Verdicts](portfolios-and-verdicts.mdx) explains.

Where the verdict rests on a run the backend found, the run comes back with it, back-annotated into a [witness](witnesses-and-traces.mdx) of the model, from which the trace is read.

## The Currently Implemented Backends

Semantifyr is a general framework, and Theta, nuXmv, Spin and Uppaal are its currently implemented backends:

- [Theta](theta.mdx) verifies an XSTS translation with unbounded integers, its verdicts exact, and is the backend every launcher's distribution carries.
- [nuXmv](nuxmv.mdx) verifies an SMV translation with unbounded integers, its verdicts exact as Theta's are.
- [Spin](spin.mdx) verifies a Promela translation with 32-bit integers, and is trusted when it finds a trace and not on a proof.
- [Uppaal](uppaal.mdx) verifies a timed-automaton translation, and is the only backend that honours `@Clock`.

The other backends are installed apart from Semantifyr, and each backend's page says what it needs on the machine.
