# Theta

[Theta](https://github.com/ftsrg/theta) is a model checking framework of the BME [Critical Systems Research Group](https://ftsrg.mit.bme.hu/en/). The backend translates a case into XSTS, Theta's transition system language, and verifies it with unbounded integers.

## Install

Put `theta-xsts-cli` on `PATH`, or install Docker, which runs Theta's `ftsrg/theta-xsts-cli` image. The VS Code extension carries its own Theta.

## Verdicts

On a model whose clock tests are all [closed](../language/specification/classes-and-behaviour/time.md#closed-clock-tests), every configuration's verdicts are exact, except those of `chc`. On any other model, a run is under-approximating: a portfolio trusts a trace it finds, not a proof.

`chc` solves the case as constrained Horn clauses with Theta's bundled Z3. It reports a violation without a trace, so a portfolio trusts it only for a proof: an invariant that holds or a state that is unreachable.

## Time

Theta realizes the [wait before every main step](../language/specification/classes-and-behaviour/time.md#the-wait-before-a-step) as a whole delay, which every clock advances by. A step waits at most one more than the largest clock bound, and a clock past its largest bound is held one above it, where every test of it reads the same; the trace gives its true value. When every clock test is closed, whole delays reach every state that dense time does. When one is not, a step that waits a fraction can reach a state no whole delay does, which is why such a run is under-approximating.

## What the backend refuses

The backend answers Not supported, naming each construct and its source line, when a case holds one of these:

- Variables of type `real`, `string`, or `any`: XSTS has integer, boolean, and enumeration variables only.
- Real literals: XSTS has no real numbers.
- String literals: XSTS has no strings.
- Array literals: the backend receives arrays split into one variable per slot and has no form for an array value.
- For-operations over anything but a range: an XSTS loop runs over an integer range.
- Clock tests that are not closed, in `chc` alone: whole delays under-approximate such a model, and Horn solving gives its verdicts without a trace.
- Clocks bounded at the largest 32-bit integer: a whole delay saturates a clock one above its largest bound, and an XSTS integer literal holds no value above 2<sup>31</sup> - 1.
