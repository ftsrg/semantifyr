# Theta

[Theta](https://github.com/ftsrg/theta) verifies the XSTS translation of a case with unbounded integers, and the verdicts of its configurations are exact, so a portfolio trusts every one of them, except those of `chc`. That configuration is Horn solving: Theta encodes the case as constrained Horn clauses and solves them with its bundled Z3. It reports a violation without a trace, so a portfolio trusts it only for a verdict that needs no witness, an invariant that holds or a state that is unreachable; a violation it reports is not trusted and carries no witness. It needs `theta-xsts-cli` on `PATH`, or Docker. It treats a `@Clock` variable as an ordinary variable. Before it runs, it reports a case Not supported when the case holds a construct listed below, naming each construct and its source line.

## What the backend refuses

- Variables of type `real`, `string` or `any`: XSTS has integer, boolean and enumeration variables only.
- Real literals: XSTS has no real numbers.
- String literals: XSTS has no strings.
- Array literals: the backend receives arrays split into one variable per slot and has no form for an array value.
- For-operations over anything but a range: an XSTS loop runs over an integer range.
