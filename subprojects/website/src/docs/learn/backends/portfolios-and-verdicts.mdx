# Portfolios and Verdicts

Verifying a case [compiles](../oxsts/compilation/index.mdx) it to a transition system and hands that to a portfolio. A portfolio is a strategy for the backend runs: which backends run under which configurations, how they run side by side, and how the verdict is decided from their answers. Where a backend found a run that shows the verdict, its [witness](../oxsts/language/library-and-output/inlined-models.md#witnesses) comes back with the verdict. The command line, Live and the VS Code extension all verify this way; `smart` is the default portfolio everywhere.

## Backends side by side

A portfolio is made of legs, each one backend under one configuration. A portfolio runs every leg whose backend is installed, each writing its files to a directory of its own in the case's directory, as many at once as a bound allows, by default the number of the machine's processors; a leg beyond the bound waits for a free place. Before its backend runs, a leg checks whether the backend can translate the model, and answers Not supported, naming the constructs it refuses, when it cannot; each [backend's page](index.mdx) lists what it refuses. A model left with no variable, no `init` and no transition is decided without any backend.

## Soundness directions

Each leg is one backend configuration, listed with the direction in which its verdicts can be trusted. An exact leg is trusted both ways. An under-approximating leg explores only part of the behaviour, so it is trusted when it finds a trace (a Failed `AG` or a Passed `EF` property) and not when it reports that none exists. An over-approximating leg is trusted the other way round. Each [backend's page](index.mdx) says which of its verdicts a portfolio trusts.

## The verdict from the answers

How the answers become one verdict is what tells the portfolios apart:

- `smart` and `theta` race their legs: the first answer that its leg's direction trusts is the verdict, and the legs still running are stopped. An answer that is not trusted does not end the race.
- `all-agree` waits for every leg and reports the verdict its trusted legs agree on, naming any untrusted leg it overrules. Trusted legs that disagree make the case Errored, since one of them is unsound.
- A single-backend portfolio reports its configuration's verdict when the leg's direction trusts it; otherwise the case is Inconclusive without a witness, and the message names the verdict it withheld, such as Spin's Passed on an `AG` property.

When no trusted answer comes, the case is Timeout when a leg ran out of time or was still running at the time limit, Errored when every leg failed, Not supported when every leg refused the model, naming each leg and the constructs it refused, and Inconclusive otherwise; the message lists what every leg reported. The time limit holds for the whole case, the compilation and the back-annotation of the witness included. The [command line's reference](../reference/command-line.mdx#verdicts) says how each verdict is reported, and [the portfolios](../reference/portfolios.mdx) lists each portfolio with its legs.

## Validation

A witness is checked by verifying it again, which is called validation: the witness model goes through the same compilation and a portfolio, the validation portfolio, the verification's own or another one, into the `validation/` directory of its case, so that the verification's artifacts and the open witness stay as they are. The witness is valid when that verification passes, since the replayed run then exists in the model and shows what the verdict says. The result is invalid when the witness verifies `FAILED`, inconclusive when it verifies `INCONCLUSIVE`, `TIMEOUT` or `NOT_SUPPORTED`, and errored when it verifies `ERRORED`, the case has no witness or the witness does not load. It carries that verdict, the portfolio, the backend that answered and its message.

The VS Code extension validates after every verdict with a witness while `semantifyr.verification.autoValidate` is on, and from **Validate Witness** on the case. Live validates every case with a witness while auto-validation is on, and from **Validate** in the case's row. The settings of both choose the validation portfolio. An OXSTS witness is named by its location in `witness.semantifyr`, a Gamma witness by the location of its case, whose last verification left the witness among its artifacts.
