# Witnesses and Traces

A trusted verdict that rests on a run the backend found, a Failed `AG` or a Passed `EF` property, comes with that run, the backend's evidence.

## The witness

The verifier back-annotates the run into OXSTS as the witness, `witness.oxsts` in the case's directory: an [inlined model](../oxsts/language/library-and-output/inlined-models.md), `witness of` the verified class, that has exactly that execution. It declares `var step: int := 0` and holds the class as `root`. Its `init` assumes `step == 0`, runs the class's `init`, assumes the value of every variable in the initial state and sets the next step; each further step is a branch of its main transition that assumes the step's number, runs the class's main transition, assumes the values of the state after it and sets the number of the next step. Its property is the class's own for a passed `EF` and its negation for a failed `AG`, so a valid witness passes when it is verified again.

Beside it, [`witness.json`](../reference/artifacts.mdx#witnessjson) holds the state of each step and [`trace.json`](../reference/artifacts.mdx#tracejson) the traced calls of each step, from which the editors and the frontends show the trace.

## The trace

The trace is what a reader reads of a case: the steps of the witness in the language of the model, as a [SysML v2 trace](../frontends/sysml-v2/traces.mdx) or a [Gamma trace](../frontends/gamma/traces.mdx), and for every language as the steps and calls of the OXSTS model. The trace of an `AG` case is an execution that breaks it, what model checkers call a counterexample.

## Validation

A witness is checked by verifying it again, which is called validation: the witness model goes through the same compilation and a portfolio, the validation portfolio, the verification's own or another one, into the `validation/` directory of its case, so that the verification's artifacts and the open witness stay as they are. The witness is valid when that verification passes, since the replayed run then exists in the model and shows what the verdict says. The result is invalid when the witness verifies `FAILED`, inconclusive when it verifies `INCONCLUSIVE`, `TIMEOUT` or `NOT_SUPPORTED`, and errored when it verifies `ERRORED`, the case has no witness or the witness does not load. It carries that verdict, the portfolio, the backend that answered and its message.

The VS Code extension validates after every verdict with a witness while `semantifyr.verification.autoValidate` is on, and from **Validate Witness** on the case. Live validates every case with a witness while auto-validation is on, and from **Validate** in the case's row. The settings of both choose the validation portfolio. An OXSTS witness is named by its location in `witness.oxsts`, a Gamma witness by the location of its case, whose last verification left the witness among its artifacts.
